ACT 1: MANUAL SINGLE-SOURCE SETUP
==================================

--- Start instances ---

  cd /home/kamil/repo/ps/8.0/install
  ./ps-node/bs_demo_cnf/bs-demo-act1-start.sh


--- 1.2 Configure source (on source_1 :4000) ---

  CREATE USER 'repl'@'%' IDENTIFIED BY 'repl';
  GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';


--- 1.3 Install and configure binlog server (on binlog_server :6000) ---

  SET sql_log_bin=0;
  INSTALL COMPONENT 'file://component_binlog_server';
  INSTALL COMPONENT 'file://component_binlog_server_rest_api';
  INSTALL PLUGIN binlog_server_relay SONAME 'binlog_server_relay.so';
  SET sql_log_bin=1;

  SET sql_log_bin=0;
  CHANGE REPLICATION SOURCE TO
    SOURCE_HOST = '127.0.0.1',
    SOURCE_PORT = 4000,
    SOURCE_USER = 'repl',
    SOURCE_PASSWORD = 'repl',
    SOURCE_AUTO_POSITION = 1,
    BINLOG_SERVER = 1,
    BINLOG_SERVER_STORAGE_URI = 'file:///home/kamil/repo/ps/8.0/install/ps-node/dn3/bs_storage/src1/'
    FOR CHANNEL 'src1';
  SET sql_log_bin=1;

  START REPLICA FOR CHANNEL 'src1';


--- 1.4 Configure downstream replica ---

On binlog_server (:6000):

  SET sql_log_bin=0;
  SET GLOBAL binlog_server.user_channel_map = 'repl_src1=src1';
  CREATE USER 'repl_src1'@'%' IDENTIFIED BY 'repl';
  GRANT REPLICATION SLAVE ON *.* TO 'repl_src1'@'%';
  SET sql_log_bin=1;

On replica_1 (:7000):

  SET sql_log_bin=0;
  CHANGE REPLICATION SOURCE TO
    SOURCE_HOST = '127.0.0.1',
    SOURCE_PORT = 6000,
    SOURCE_USER = 'repl_src1',
    SOURCE_PASSWORD = 'repl',
    SOURCE_AUTO_POSITION = 1;
  SET sql_log_bin=1;
  START REPLICA;


--- 1.5 Write data, observe replication ---

On source_1:

  CREATE DATABASE demo;
  USE demo;
  CREATE TABLE t1 (id INT AUTO_INCREMENT PRIMARY KEY, msg VARCHAR(100));
  INSERT INTO t1 (msg) VALUES ('hello from source_1');
  INSERT INTO t1 (msg) VALUES ('second message');
  SELECT SLEEP(2);
  FLUSH BINARY LOGS;

  INSERT INTO t1 (msg) VALUES ('third message');
  INSERT INTO t1 (msg) VALUES ('fourth message');
  INSERT INTO t1 (msg) VALUES ('fifth message');
  SELECT SLEEP(2);
  FLUSH BINARY LOGS;

  INSERT INTO t1 (msg) VALUES ('sixth message');
  INSERT INTO t1 (msg) VALUES ('seventh message');
  SELECT SLEEP(1);
  FLUSH BINARY LOGS;

  INSERT INTO t1 (msg) VALUES ('eighth message');

  -- Now we have 4+ binlog files: src1-bin.000001 .. src1-bin.000004
  -- (source_1 uses log_bin=src1-bin, so archived files keep that name)

On replica_1 — data arrives:

  SELECT * FROM demo.t1;

On binlog_server — NO data (archive-only, does not apply):

  -- ERROR 1049: Unknown database 'demo'


--- 1.6 Monitoring via PFS tables (on binlog_server) ---

  SELECT * FROM performance_schema.replication_binlog_server_status\G
  SELECT * FROM performance_schema.replication_binlog_server_storage\G

         PREVIOUS_GTID_SET, LAST_GTID_SET
    FROM performance_schema.replication_binlog_server_archive

--- 2.5 Bulk insert (watch dashboard update) ---

On source_1 — run this procedure that inserts data continuously and rotates
the binlog every ~5 seconds, for about 1 minute total (~12 new files):

  USE app1;
  DELIMITER //
  CREATE PROCEDURE demo_bulk_load()
  BEGIN
    DECLARE batch INT DEFAULT 0;
    WHILE batch < 12 DO
      -- Insert a batch of rows
      SET @i = 0;
      WHILE @i < 50 DO
        INSERT INTO orders (product, amount)
          VALUES (CONCAT('Bulk_', batch, '_', @i), ROUND(RAND()*100, 2));
        SET @i = @i + 1;
      END WHILE;
      -- Rotate binlog so a new file appears in the dashboard
      FLUSH BINARY LOGS;
      -- Wait 5 seconds before next batch
      DO SLEEP(5);
      SET batch = batch + 1;
    END WHILE;
  END //
  DELIMITER ;

  CALL demo_bulk_load();

  -- Watch the Archive tab: a new src1-bin.* file appears every ~5 seconds
  -- Total: ~12 new files over 1 minute, ~600 rows inserted

===============================================================================
KEY MESSAGES
===============================================================================

  - Archive-only: BS does NOT apply transactions — it stores binlogs only.
  - Multi-source: multiple independent clusters archived to one BS instance.
  - Selective replication: replicas choose which source via user-channel routing.
  - GTID-native: everything uses GTIDs, no position-based replication needed.
  - Search/PITR: find files for point-in-time recovery by timestamp or GTID.
  - REST API + Dashboard: full HTTP interface for automation and monitoring.
  - Encryption: at-rest encryption with keyring-managed keys (optional).
  - Orchestrator: standard tools can discover the topology (with limitations).
